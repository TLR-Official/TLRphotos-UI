## 一、背景与目标

现有作品集已具备「大标签聚合」能力（V3.2.0-beta 落地 `/tags?with_counts=1`），但标签体系仅有单层，用户无法按机型、车架等细分维度检索；同时审核端缺少队列约束与申诉责任判定闭环。

本迭代目标：
1. 建立大标签 → 前置标签 → 细分标签的三层体系，提升检索精度；
2. 明确标签下钻/返回的交互规则，做到“一键直达、不做复杂交互”；
3. 规范审核流转：用户端排队、审核端顺序审核、最高权限端专责申诉；
4. 补齐申诉重审与审核员责任判定，新增热门图片滚动推荐。

## 二、模块一：三层标签体系

### 2.1 层级结构

| 层级 | 定位 | 示例 | 是否必填 |
|------|------|------|----------|
| 第一层 | 大标签（分区） | 航空 / 铁路 / 公路 | 必填 |
| 第二层 | 前置标签（子方向） | 以航空为例：宽体、窄体等（手稿示例，**待确认**） | 必填 |
| 第三层 | 细分标签（**建议性**） | 飞机机型、车架等 | 选填 |

**说明**：
- 第三层手稿明确标注为「建议」，不作为强制录入项；
- 第二层标签为进入第三层的前置条件（手稿注「二层标签（前置）」）。

### 2.2 三层录入方式

- **逐层选择**：大标签 → 前置标签 → 细分标签；
- **直接搜索**：允许跳过层级，直接搜索目标标签；
- **查看文件**：支持查看与标签关联的文件/说明（手稿标注「查看文件」，具体形态待确认）。

## 三、模块二：标签浏览交互（以航空为例）

### 3.1 下钻与返回

- 一层大标签「航空」→ **点击**（仅点击，不做长按、悬停等复合手势）→ 展示所有航空类照片；
- 点击后进入第二层标签；第二层可继续进入第三层；
- **每一层均必须支持「点击返回」回到上一层**，并最终可返回原详情页；
- 手稿对此多次圈注，属核心交互要求，不可省略。

### 3.2 标签点击行为

- 点击标签 → 显示相关图像；
- 支持「显示并添加标签」「显示开关」等操作（手稿此处字迹潦草，**具体语义待确认**）；
- 「想看那个」→ 从浏览态直接定位到目标标签的结果集。

### 3.3 展示形态（保留）

- 手稿右侧标注「标签（保留）」，附四图网格与边框草图，倾向**图标 / 卡片式标签入口**；
- 另注「小标签（放大 / 缩小）」，涉及标签尺寸与密度控制，**具体规则待确认**。

### 3.4 设计红线

> **点完第二层 / 第三层标签后直接跳转结果页；切记不要做太复杂（但功能不能少）。**

- 层级跳转必须一步到位；
- 不得叠加二次确认、多段动画、多层弹窗等复杂流程；
- 功能完整性（搜索、返回、筛选）不得因简化交互而缺失。

## 四、模块三：审核流转

### 4.1 用户端流程

```
上传图片
  → 待审核 + 排队队列
      → 通过   → 已入库图片（按新上传时间排序）→ 易于查阅
      → 未通过 → 拒绝原因（含审核员编号，详情页同显）→ 可申诉
```

- **排队队列需按大标签分类**到对应分区队列（手稿注：需优化高峰时段处理能力）；
- 未通过记录必须展示**拒绝原因**与**审核员编号**，详情页同步显示，便于追责与申诉举证。

### 4.2 审核端流程（以航空分区为例）

- 展示所属分区待审核队列；
- **建议仅允许「按顺序审核」：审完一张才能审下一张**；
- 目的：避免审核员跳审导致低优先级图片长期堆积；
- 手稿注「显示待审核（建议：仅允许…）」，该项为建议采用，**是否强制待确认**。

### 4.3 最高权限端

- 职责范围：**仅处理高级申诉**及其审核；
- 不参与常规照片审核队列，避免与审核端职责重叠。

## 五、模块四：申诉与重审

### 5.1 流程

1. 用户发起申诉（**包括原先被拒图片**）；
2. 进入重审流程；
3. 裁决分支：
   - 判定为**审核员失误** → 图片直接通过；
   - 判定为**审核员违规** → 对审核员给予「警告或处罚」。

### 5.2 申诉规范

- **不允许在申诉内容中发布无关言论**；
- 需在产品层做输入约束（长度限制、无关内容提示），而非仅依赖人工判断。

### 5.3 与现有能力的关系

- 现有 V4.0.0-beta 已落地申诉状态机（`/my/appeals`、`admin:appeals`）；
- 本迭代需在其基础上补充**审核员责任判定**与**审核员编号展示**。

## 六、模块五：热门图片

- 需新增热门图片能力（可与现有 `is_hot` 意愿标记、审核员「确认热门」操作衔接）；
- 较热门图片支持**滚动播放**（首页或分区页轮播）；
- 提供**推荐页**入口展示热门作品；
- 与既有规则的关系：热门图片不可召回（V4 召回机制），本迭代需保持一致。

## 八、优先级与排期建议

| 优先级 | 模块 | 理由 |
|--------|------|------|
| P0 | 审核流转 + 申诉重审 | 直接影响审核效率与责任闭环，改动集中在后端状态机 |
| P1 | 三层标签体系 | 数据模型变更，需迁移与兼容现有单层标签 |
| P2 | 标签浏览交互 | 依赖 P1 数据结构，纯前端交互 |
| P3 | 热门图片滚动与推荐页 | 依赖现有热门标记，可独立迭代 |
