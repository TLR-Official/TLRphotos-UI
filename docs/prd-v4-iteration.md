## 一、背景与目标

现有审核工作流（V3.x）缺乏以下能力：

1. 用户无法感知与自己相关的系统事件（点赞、下载、处罚、申诉结果等），需主动查询；
2. 审核员误操作后无纠错手段，误审图片一旦入库难以撤回；
3. 论坛缺乏社区化定位与轻量审核策略，内容形态单一；
4. 站点缺少官方新闻发布渠道与品牌展示页。

本迭代目标：补齐通知与审核纠错闭环，完善论坛社区生态，开放官方内容发布能力，完成品牌展示页。

## 二、模块一：通知与审核纠错系统（P0）

### 2.1 通知中心

**需求描述**：在用户个人中心新增「通知中心」页面，聚合展示所有与当前用户相关的系统通知。

**通知类型清单**：

| 类别 | 通知项 | 触发方 |
|------|--------|--------|
| 内容型 | 作品被点赞 | 其他用户行为 |
| 内容型 | 作品被下载 | 其他用户行为 |
| 内容型 | 作品被评为热门（Hot） | 审核员/管理员操作 |
| 管理型 | 一级/二级处罚通知 | 管理员处罚操作 |
| 管理型 | 申诉回执（通过/驳回） | 申诉裁决流程 |
| 管理型 | 作品召回通知 | 审核召回流程（见 2.3） |

### 2.2 申诉结果通知（双向闭环）

**需求描述**：申诉裁决结果必须回执至用户通知中心，形成「申诉 → 裁决 → 回执」闭环。

| 场景 | 系统行为 |
|------|----------|
| 申诉通过 | 图片状态置为已入库（approved），并向用户推送入库通知 |
| 申诉不通过 | 推送驳回回执，回执支持跳转至详情页查看驳回原因 |
| 正常一次性过审 | **不发送任何通知**（避免通知噪音，此为刻意设计） |

**补充规则**：所有未过审图片统一删除精修图、仅保留预览图；该现有规则在申诉全流程中继续生效。

### 2.3 审核失误召回机制（核心）

**需求描述**：为审核员提供误操作纠错通道，按召回时效分两级处理。

**触发条件**：审核员误点通过，或未仔细查看图片内容即通过（低级失误）。

**两级召回规则**：

| 时效 | 行为 | 是否通知用户 |
|------|------|--------------|
| 通过后 **3 分钟内** | 静默撤回，图片回到待审核队列重新审核 | 否（无通知召回） |
| 通过后 **超过 3 分钟** | 必须填写召回原因，图片回到待审核队列 | 是，推送召回通知 |

**权限规则**：
- 高权限账号（超管/分区主管）：可召回任意审核员的图片；
- 普通审核员：仅可召回本人审核的图片。

**召回通知模板**：

> xxx 您好，您的作品《xxx》于 xxxx 年 xx 月 xx 日 xx 时 xx 分被召回重新审核，原因：xxx。详情请见「待审核」页面。

**例外规则**：Hot（热门）图片**不允许召回/撤回**。

### 2.4 管理端界面优化

1. 新增「分配管理」入口：管理员可指派/转移审核任务；
2. 审核员可查看自己名下已处理的作品列表（工作量可视化）；
3. 用户侧支持撤回未裁决的申诉。

## 三、模块二：论坛（P1）

### 3.1 定位与边界

- 论坛定位为**讨论交流社区**（问答、日常分享）；
- 「技术交流」类内容不属于公开论坛范畴；如有需要，仅限内部人员使用（不纳入本迭代）。

### 3.2 标签体系

- 仅保留 **3 个大标签（板块）**：航空、铁路、公路；
- 文章类内容归入相应板块，不单独设板块；
- **决策**：不做小标签体系（站长已确认）。

### 3.3 审核策略

- 发帖采用**后置审核**：直接发布，不做前置拦截；
- 「论坛小审」：仅巡查评论区违规内容（引战、辱骂、广告等）；
- 设立独立的**论坛审核权限角色**，职责限定为：浏览论坛并删除违规评论/内容，不参与图片审核。

### 3.4 互动结构

- 楼层结构：楼主发言 → 一级评论（评论楼主）→ 二级回复（平铺展示）；
- 复用现有三级评论体系（subject_type=thread，V3.1.0 已落地）；
- 被回复者收到「回复 @xxx」提示。

## 四、模块三：新闻区（P2）

### 4.1 运营模式

- 页面设计保留现状，功能实现优先级较低；
- 设立**新闻编辑专用账号**（走现有权限体系），由总负责人完成事务交接后为其开通权限；
- 首批仅开放「航空」方向。

### 4.2 编辑器

- 结构：标题 + 正文 + 配图；
- 配图来源：**直接调用站内图库选图**（复用现有照片检索能力，支持随时更换配图），不允许本地上传新闻配图。

### 4.3 图片使用授权规范

1. 选图界面增加**授权确认勾选**：作者承诺允许在不改变图片色彩与内容的前提下使用，且使用时必须显著标注署名；
2. 版权标注格式：`@作者名 ©TLRphotos 2026 版权所有`。

## 五、模块四：「关于我们」页面（P3）

### 5.1 优先级

- 实现成本最低，但排在全部模块之后执行（站长明确指示）。

### 5.2 内容结构

| 区块 | 内容 |
|------|------|
| 团队介绍 | 创始人 / 技术 / 审核 / 航空审核 角色卡片 + 简介文案 |
| 站点数据 | 已开站天数、已入库作品数 |
| 支持我们 | 入口预留（投票/捐赠，形式待定） |

**注**：团队简介文案由站长亲自撰写，内容待提供；页面框架可先行开发。

## 六、优先级与排期建议

| 优先级 | 模块 | 理由 |
|--------|------|------|
| P0 | 通知与召回系统 | 审核纠错是审核流运转的基础保障 |
| P1 | 论坛 | 核心社区功能，依赖现有评论体系，改造成本低 |
| P2 | 新闻区 | 依赖运营账号与权限交接（外部依赖） |
| P3 | 关于我们 | 静态页面，随时可插入，不阻塞其他模块 |
