## 一、项目概述

### 1.1 背景

TLRphotos 是面向交通摄影爱好者（航空 / 铁路 / 公路三大分区）的作品分享与审核社区，现有 Web 端以桌面浏览器为主要设计基准。站长手绘规划稿已明确提出「并完成个手机端」「大屏 / 移动端 / 手机端适配」的要求，且移动端是目标用户的主要拍摄后即时浏览场景（机场、机位、车站现场），移动端体验直接决定社区的留存与投稿转化。

### 1.2 目标

1. 移动端全站可用：用户端 18 个页面全部在 ≤430px 视口下达到「无需横滑、无需缩放、核心操作 ≤3 步可达」；
2. 移动端投稿转化率不低于桌面端的 80%（上传全链路移动端可走通）；
3. 审核端（审核员移动审图）作为增强目标，不做首期强制要求，但信息架构须预留；
4. 保持现有设计红线：白底黑字、无暗色模式、三色体系（淡蓝 / 淡紫 / 深蓝，accent = blue-700）、无紫色残留、论坛去 emoji 纯文本统计。

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 包含 | 用户端全部页面、管理端只读浏览（列表/详情查看）、PWA 基础能力 |
| 不包含（首期） | 管理端复杂操作移动化（封禁表单、审核工具集九项）、原生 App、小程序 |
| 待二期 | 管理端审核工具集（直方图/九宫格等九项）移动化、消息推送（Web Push） |

### 1.4 名词约定

- **视口分档**：`S` ≤360px（小屏）、`M` 361~430px（主流手机）、`L` 431~768px（大屏手机/折叠展开）；>768px 走现有桌面布局；
- **安全区**：iOS 刘海与底部 Home Indicator 区域，统一以 `env(safe-area-inset-*)` 处理；
- **热区**：可触控元素的最小点击区域，本 PRD 强制 ≥44×44px（WCAG 2.5.5 / Apple HIG 对齐）。

## 二、架构选型

### 2.1 选型结论

**采用「响应式为主干 + 路由级独立移动页为补充」的混合架构。**

- 默认：同一 URL、同一组件树，经 CSS 断点（Tailwind `sm:`/`md:`）与条件渲染适配移动端；
- 例外（独立移动路由）：仅当桌面版交互范式在移动端**无法降级**时，挂载 `/m/*` 前缀的独立页面。

### 2.2 选型依据

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 纯响应式（单组件树） | SEO/分享链接唯一；维护成本最低；与现有代码零冲突 | 复杂页（上传水印编辑器）难降级 | 主干采用 |
| 纯独立移动站（m.tlrphotos.com） | 体验可深度定制 | 双代码库、双 SEO、链接分裂、与 Monorepo 现状冲突 | 否决 |
| 响应式 + 路由级独立页 | 兼顾维护成本与复杂场景体验 | 需约定分流规则 | **采用** |

### 2.3 分流规则（技术适配说明）

1. **服务端不分流**：Nginx 不做 UA 重定向，全部请求回同一 SPA 入口（`index.html`），避免 Cloudflare 缓存键分裂；
2. **客户端分流**：应用启动时经 `matchMedia('(max-width: 768px)')` + `navigator.userAgent` 双重判定，命中移动端的复杂页重定向至 `/m/*` 对应路由；
3. **独立移动页清单（首期仅 2 个）**：
   - `/m/upload`：上传页移动版（桌面版水印编辑器依赖拖拽与滚轮，移动端改为分步表单，见 6.4）；
   - `/m/photo/:id/edit`：照片编辑移动版；
4. **能力探测优于 UA 探测**：水印编辑器是否启用触摸版，以 `'ontouchstart' in window` 与指针类型（`pointer: coarse`）判定，而非单纯视口宽度——折叠屏展开态仍可用桌面编辑器；
5. **构建产物**：同一 Vite 构建，`/m/*` 组件走动态 `import()` 分包，桌面端用户不下载移动页 chunk，反之亦然；
6. **既有约束沿用**：Cloudflare WAF `/api/` 跳过规则、后端 `127.0.0.1:3001` 反代、静态资源 hash 防缓存——移动端无任何例外通道。

### 2.4 与后端契约的关系

- **零新增接口原则**：移动端复用现有 `api.md` 全部契约；
- 允许新增的纯展示参数（如列表 `page_size` 移动端默认 12、桌面 24）不视为契约变更，但需在 api.md 备注；
- 若移动端确需新端点（如设备订阅推送），先更新 `backend/docs/api.md` 再开发（项目强制规则）。

## 三、目标用户分析

### 3.1 用户画像

| 画像 | 占比（预估） | 特征 | 移动端核心诉求 |
|------|--------------|------|----------------|
| 航空摄影爱好者 | 55% | 机场周边蹲点拍摄，现场修图后即时分享 | 现场快速上传、查看同机型作品、注册号检索 |
| 铁路摄影爱好者 | 30% | 沿线/车站拍摄，车次信息敏感 | 车次/车型标签筛选、图库按分区浏览 |
| 公路/巴士爱好者 | 10% | 街拍拍车 | 快速上传、浏览同城作品 |
| 潜水浏览者 | 5% | 不注册，纯看图 | 免登录浏览、图片加载快、下载带水印原图 |
| 审核员/管理员 | <1% | 站内治理 | 移动端查看队列与详情（首期只读） |

### 3.2 核心需求排序（移动端视角）

1. **看**：刷图、搜图（注册号/标签/分区）、看详情、下载；
2. **传**：手机相册直传（占移动端投稿预估 70%+）、补充元数据、查审核进度；
3. **互动**：点赞、评论、论坛浏览与发帖；
4. **感知**：通知（点赞/下载/处罚/申诉回执）、公告横幅；
5. **管自己**：个人主页、我的作品、申诉发起、资料维护。

### 3.3 典型使用场景

| 场景 | 网络环境 | 单手可操作 | 关键路径 |
|------|----------|------------|----------|
| 机位现场传图 | 4G/弱网 | 是 | 上传 → 填标题/注册号 → 提交 → 收到审核结果通知 |
| 通勤刷图 | 4G/5G | 是 | 首页 → 画廊分区 → 详情 → 点赞/下载 |
| 被驳回后处理 | 任意 | 是 | 通知中心 → 驳回详情 → 修改重传或发起申诉 |
| 深夜论坛 | Wi-Fi | 是 | 论坛 → 板块 → 帖子详情 → 回复 |
| 活动公告触达 | 任意 | — | Top Banner → 公告详情 |

### 3.4 潜在期望（推演）

- 上传后离线可排队（弱网恢复自动续传）——列为二期增强；
- 通知有未读角标与震动反馈（PWA 下受限，见 10.4）；
- 浏览历史与收藏（现系统无收藏，**待确认**是否纳入）。

## 四、全站架构设计

### 4.1 信息架构（移动端）

```
┌─ 底部主导航（5 项，常驻）
│   首页 │ 画廊 │ [＋上传] │ 论坛 │ 我的
│
├─ 首页          /            → 热门轮播、公告横幅、最新入库、分区入口
├─ 画廊          /gallery     → 分区 Tab + 标签筛选 + 注册号搜索
├─ 上传          /m/upload    → 独立移动页（分步表单）
├─ 论坛          /forum       → 板块列表 → 帖子流 → 详情/发帖
└─ 我的          /profile     → 个人中心聚合页
    ├─ 通知中心   /notifications
    ├─ 我的作品   /my-works
    ├─ 我的申诉   /my/appeals
    ├─ 公开主页   /users/:id
    └─ 设置      （资料/改密/换绑邮箱）

二级页（不驻主导航）：
照片详情 /photo/:id、搜索结果 /search、新闻区 /news、文章详情 /news/:id、
关于我们 /about、标签聚合 /tags、申诉发起页、登录注册 /auth
```

### 4.2 导航体系规则

1. **底部主导航**：固定 5 项，高 56px + 安全区 padding；「上传」为中央凸起主按钮（直径 52px，深蓝实底，仅登录可点，未登录点击引导至 /auth）；
2. **顶部条**：仅放品牌 Logo（左）+ 通知铃铛（右，未读角标 blue-700 数字徽章）；**管理端入口不在移动端顶部出现**（保持「管理后台无顶栏」的既有隔离原则）；
3. **二级页导航**：顶部返回栏（左箭头 + 页标题），右上角最多 1 个动作位；
4. **路由与滚动**：每个一级 Tab 独立记忆滚动位置；二级页返回时还原；
5. **深链**：通知/申诉跳转必须可直达对应详情（`related_type` 路由表保持与桌面端一致）。

### 4.3 状态可见性原则（移动端强化）

- 任何异步操作必须有「加载中 → 成功/失败」的可见反馈；
- 弱网（`navigator.connection.effectiveType` ∈ {2g, 3g}）下：图片默认加载缩略图而非预览图、禁用预取下一张、上传显示断点续传提示。

## 六、核心页面详细设计（布局 / 信息层级 / 触控适配）

> 每页按「信息层级（自上而下优先级）→ 布局逻辑 → 触控与手势 → 异常场景」四段式描述。仅展开对移动端有差异化要求的页面；未列出的页面按第五章验收要点执行响应式降级。

### 6.1 首页 `/`

**信息层级**：
1. 公告横幅（Top Banner，可关闭，关闭状态 localStorage 记忆 7 天）
2. 热门图片轮播（横滑卡片，高度 200px，Snap 滚动）
3. 三大分区入口（航空/铁路/公路，等宽三枚入口卡）
4. 最新入库（双列网格，无限滚动）
5. 全局页脚

**布局逻辑**：单列流式；轮播区左右留 16px 边距，卡片宽 85% 制造「可横滑」的视觉线索；分区入口卡高 72px，图标 + 文字横向排列。

**触控与手势**：
- 轮播：水平滑动，支持惯性；点击进详情；不做自动播放（省流量与电量，**待确认**）；
- 最新入库：双列网格项间距 8px，图片 1:1 裁切封面；
- 下拉刷新：仅在列表顶部触发，触发阈值 70px，带文字提示「松开刷新」。

**异常场景**：
- 公告接口失败 → 横幅位整体隐藏，不留空白；
- 热门为空 → 隐藏轮播区，最新入库上移；
- 弱网 → 轮播只取首张，其余懒加载。

### 6.2 画廊 `/gallery`

**信息层级**：分区 Tab（吸顶）→ 筛选条（热门标签 chips 横向滚动 + 搜索入口）→ 瀑布流。

**布局逻辑**：
- 分区 Tab 高 44px，选中态深蓝下划线 2px；吸顶于顶部导航之下；
- 热门标签 chips 单行横滑（top12，与桌面端 `/tags?with_counts=1` 一致），过多时收起进「全部标签」抽屉；
- 瀑布流双列，`masonry` 逻辑按宽高比估算占位，避免 CLS；
- 注册号搜索提示保留在搜索框 placeholder：「搜注册号 / 标题 / 标签」。

**触控与手势**：
- 标签抽屉：底部弹出（Bottom Sheet），高度 70vh，支持下滑关闭；
- 列表项点击进详情；长按不出现桌面端 tooltip；
- 返回画廊时还原 Tab、筛选与滚动位置。

**异常场景**：筛选无结果 → 空态插画 + 「清除筛选」按钮；注册号格式非法 → 搜索框下红字提示，不阻断浏览。

### 6.3 照片详情 `/photo/:id`

**信息层级**：图片区 → 标题/作者/注册号 → 数据行（x 回复 · x 点赞 · x 浏览，纯灰文本）→ 操作区 → 评论区。

**布局逻辑**：
- 图片区：宽高比自适应，`object-contain`，背景浅灰 #f5f5f5；双击放大、双指缩放（pinch）、缩放时禁止页面滚动；
- 数据行严格沿用论坛式纯文本风格（无图标），字号 12px 灰色；
- **下载按钮固定于底部安全栏上方**：宽屏通栏、bg-blue-600 白字加粗、高 48px，与现有「高对比下载按钮」规范一致；未过审照片所有者可见，其余角色按现有权限隐藏；
- 评论区：三级嵌套在移动端改为「缩进 ≤2 级，第三级平铺 + 『回复 @xxx』前缀」，与后端平铺存储对齐；单条评论操作（回复/删除）收进长按或右侧「…」。

**触控与手势**：
- 图片双击缩放（1x ↔ 2.5x），pinch 范围 1x~4x；
- 左右滑切上/下一张（仅在来源列表语境内生效，如从画廊进入）；
- 评论输入框聚焦时顶起（`visualViewport` 监听 + `scrollIntoView`），避免被键盘遮挡。

**异常场景**：
- 未过审+非所有者 → 现有「审核中」占位图，禁止缩放；
- 已删除/被召回 → 全屏空态「作品已被召回或删除」+ 返回按钮；
- 下载失败 → 底部 Toast，3 秒自动消失，可重试。

### 6.4 上传 `/m/upload`（独立移动页）

**设计动机**：桌面上传页的水印编辑器（拖拽/滚轮缩放/工具面板）在小屏不可用，故拆分为分步表单。

**分步结构（4 步）**：
1. **选图**：相册选择 / 调用拍照（`<input type="file" accept="image/*">`，单文件，沿用「禁止多选」红线）；选后显示预览与大小；
2. **填信息**：标题（必填）、描述（必填）、分区（三选一卡片）、标签（热门 chips + 自定义输入）、**注册号（必填，自动大写 + 正则双校验，与桌面一致）**、热门意愿勾选（仅审核参考）；
3. **水印设置（简化版）**：位置九宫格点选 + 字号三档（小/中/大）+ 透明度滑杆；预览实时渲染（复用现有 scaleFactor 同源逻辑）；水印文案固定 TLRphotos 不可改（红线）；
4. **确认提交**：信息摘要卡 + 提交按钮；提交中全屏进度遮罩（OSS 预签名直传进度百分比）。

**触控与手势**：
- 每步底部「上一步 / 下一步」通栏按钮；步进条置于顶部（4 圆点 + 连线）；
- 注册号输入自动转大写、过滤非法字符（`A-Z0-9-`，2~20 位）；
- 步骤间数据全部留存，杀进程重进后可从草稿恢复（localStorage，仅存元数据不存图）。

**异常场景**：
- 弱网/断网 → 进度遮罩显示「网络异常，将自动重试」，指数退避 3 次后转人工重试按钮；
- 400 REGISTRATION_REQUIRED → 跳回第 2 步并定位注册号输入框；
- 403 HUMAN_VERIFICATION_REQUIRED → 复用现有人机验证弹窗（Turnstile compact）；
- 文件超限时前端先拦截（读取 `File.size`），提示压缩后再传。

### 6.5 论坛（`/forum` 系列）

- 帖子流项：标题（至多两行截断）+ 纯文本统计行「x 回复 · x 点赞 · x 浏览」（沿用 V3.2.0 去 AI 化红线，**禁止任何图标/emoji**）；
- 帖子详情：楼主发言卡与评论区视觉分层（楼主卡带左边框 3px 深蓝）；三级回复平铺 + 「回复 @xxx」；
- 发帖页：Markdown 工具栏收进折叠条（默认收起，点「Aa」展开）；预览切换 Tab 置于编辑器上方；人机验证内联于提交按钮上方；
- 论坛审核端：首期移动端**不做**，审核员提示「请使用桌面端处理」。

### 6.6 通知中心 `/notifications`

- 列表项：类型文字徽章（点赞/下载/处罚/申诉/召回）+ 摘要一行截断 + 相对时间；未读加粗 + 左侧 4px 蓝点；
- 顶部操作：「全部已读」（文字按钮，右对齐）；
- 加载更多：滚动到底自动加载，底部显示「加载中/没有更多了」；
- 点击跳转按 `related_type` 路由表：photo→详情、appeal→申诉详情、penalty→个人主页处罚卡、announcement→公告详情；
- 处罚类通知样式警示但**不使用红色大面积填充**（保持三色体系，用深蓝左边框 + 浅蓝底）。

### 6.7 我的与个人中心

- `/profile` 聚合页：头像/昵称卡 → 数据三格（入库/点赞/下载）→ 功能列表（我的作品、我的申诉、通知中心、公开主页、设置）；
- `/my-works`：顶部三状态分段控件（已通过/待审核/未通过），未通过卡片显示驳回理由（两行截断 + 「查看详情」）+「申诉」按钮（409 已申诉则置灰显示状态）；
- `/users/:id` 公开主页：顶部资料卡（含地区省份、加入天数、作品统计）→ 活跃处罚公示卡（如有）→ 作品分区 Tab → 论坛发帖记录。

### 6.8 公告与新闻

- Top Banner：移动端高度 48px，单行标题 + 右箭头；点击进公告详情（封面 16:9 + 标题 + 正文）；右上角关闭按钮热区 44×44；
- 新闻区列表：封面 16:9 通栏 + 标题两行 + 日期；正文图片 `max-width:100%` 自适应，版权标注 `@作者名 ©TLRphotos 2026 版权所有` 置于图下 12px 灰字。

## 七、交互规范

### 7.1 触控热区与间距

| 元素 | 最小热区 | 相邻热区间距 |
|------|----------|--------------|
| 底部主导航项 | 64×48px | — |
| 通栏按钮 | 全宽×48px | ≥12px |
| 图标按钮（关闭/返回/铃铛） | 44×44px | ≥8px |
| 列表项 | 全宽×≥56px | ≥1px 分隔线 |
| 标签 chip | ≥32px 高，水平 padding 12px | ≥8px |

- 所有热区以透明 padding 扩展实现，不依赖视觉边界；
- 屏幕底部 24mm（拇指热区）优先放置主操作，危险操作（删除/撤回）不放该区域。

### 7.2 手势白名单

| 手势 | 允许场景 | 禁止场景 |
|------|----------|----------|
| 双击缩放 | 照片详情图片 | 全站其他任何位置（防误触缩放） |
| Pinch 缩放 | 照片详情图片 | 列表/表单页（viewport 锁 `user-scalable=no`） |
| 水平滑切 | 详情页上/下一张、首页轮播 | 表单页（防误滑丢输入） |
| 下拉刷新 | 首页/画廊/通知/帖子流 | 详情页、表单页 |
| 左滑删除/操作 | **不使用** | 全站统一（左滑返回系统手势冲突） |

### 7.3 反馈体系

- **即时反馈**：所有可点元素 `:active` 态透明度 0.7 或底色加深，无延迟；
- **操作结果**：轻量结果用 Toast（底部，2~3s）；需用户知晓的结果用对话框（申诉提交成功等）；
- **防连点**：提交类按钮点击后立即进入 loading 置灰，直至请求完成（沿用桌面端防连点约定）；
- **震动反馈**：不使用（避免侵入感）。

### 7.4 加载与骨架

- 首屏页面（首页/画廊/详情）使用骨架屏，禁止白屏转菊花；
- 列表分页：滚动加载，到底后显示「加载中」，失败时显示「加载失败，点击重试」；
- 图片统一走缩略图 → 预览图渐进；`CachedImage` 逻辑与桌面端一致（鉴权 token 透传不丢失）。

### 7.5 空态与错误页

- 空态三要素：插画（或图标）+ 一句话说明 + 主行动按钮；无按钮的空态需明示「暂无内容」；
- 401 → 引导登录（返回地址记忆）；403 → 文案说明原因（PERMISSION_DENIED/处罚提示）+ 回首页；404 → 「页面不存在」+ 回首页；5xx → 「服务繁忙，请稍后重试」+ 重试按钮；
- 所有 API 空响应/非 JSON 响应按现有 client.ts 规范兜底，禁止抛「Unexpected end of JSON input」裸错误给用户。

## 八、排版标准

### 8.1 字体与字号阶梯

- 字体族：系统栈 `-apple-system, "PingFang SC", "Noto Sans SC", sans-serif`，不引入 Web 字体（省流量）；
- 字号阶梯（rem 基准不变）：

| 用途 | 字号/行高 | 字重 |
|------|-----------|------|
| 页面主标题 | 20px / 28px | 600，纯黑 |
| 卡片/列表标题 | 16px / 24px | 500 |
| 正文 | 14px / 22px | 400 |
| 辅助/统计文本 | 12px / 18px | 400，灰色 |
| 最小文本（版权/时间） | 11px / 16px | 400 |

### 8.2 间距与栅格

- 页面左右边距 16px；卡片内边距 12px；卡片间距 12px；
- 8px 间距体系（8/12/16/24/32），禁止出现 7px、13px 等零散值；
- 圆角统一：卡片 12px，按钮 8px，chip 999px；
- 阴影收敛：仅浮层（Bottom Sheet、弹窗）使用 `shadow-lg`，平面卡片一律边框 1px #e5e5e5。

### 8.3 色彩（沿用现有红线）

- 背景白、正文黑；主题三色：淡蓝、淡紫（仅点缀）、深蓝（accent，blue-700 系）；
- 禁止紫色系残留；直方图蓝色通道等语义色不在此限；
- 通知未读角标、Tab 选中、主按钮统一深蓝；警示仅用深蓝左边框 + 浅蓝底，不引入红色系（系统级错误 Toast 除外）；
- 无暗色模式，`prefers-color-scheme` 媒体查询不生效（既有规则延续）。

### 8.4 安全区与适配细节

- 底部主导航、固定下载按钮、提交按钮容器均加 `padding-bottom: env(safe-area-inset-bottom)`；
- iOS 输入框聚焦自动放大问题：输入框字号 ≥16px 或 viewport 已锁缩放；
- 横屏：不强制锁横竖屏；图片详情横屏时图片区高度 `100dvh`；
- 折叠屏展开 >768px 自动切回桌面布局，无中间断裂态。

## 九、用户引导体系

### 9.1 新手引导（Onboarding）

| 触发时机 | 形式 | 内容 | 关闭/跳过 |
|----------|------|------|-----------|
| 首次安装访问首页 | 单屏浮层（非全屏） | 「传图需注册，浏览可随意」+ 注册/随便看看 | 点遮罩关闭，localStorage 记忆 |
| 首次进入上传页 | 步骤条上方提示条 | 「共 4 步：选图 → 信息 → 水印 → 提交」 | 不再显示开关 |
| 首次上传完成 | 成功页内联卡 | 「审核通过后会通知你；可在我的作品查看进度」 | 自动 |

原则：总步骤 ≤1 屏、文字 ≤30 字、全部可跳过；不做强制多页轮播引导。

### 9.2 功能提示（Feature Tips）

- **注册号必填提示**：上传第 2 步注册号输入框下方常驻灰字「如 B-1234 / G-DCDE，2~20 位字母数字或连字符」；格式错误时红字实时提示；
- **热门意愿勾选说明**：勾选框右侧「？」图标，点击弹出 Bottom Sheet 说明「仅作为审核参考，不保证评为热门」；
- **申诉入口提示**：未通过作品卡的「申诉」按钮长按/点击「？」说明申诉规范（禁止无关言论）；
- **审核排队说明**：我的作品-待审核 Tab 顶部常驻灰字「按分区排队审核，请耐心等待」；
- 提示触发记录统一存 localStorage（key 前缀 `tip_`），同一提示最多出现 3 次。

### 9.3 异常场景指引

| 场景 | 指引文案要点 | 出口 |
|------|--------------|------|
| 邮箱验证码收不到 | 检查垃圾箱 → 换绑邮箱入口 → 60s 倒计时 | 重发按钮 |
| 上传失败（网络） | 「网络异常，进度已保留，重试将继续」 | 重试/存草稿退出 |
| 被驳回 | 展示驳回理由 + 审核员编号（站内编号）| 修改重传 / 发起申诉 |
| 账号被处罚 | 个人主页处罚卡说明等级、原因、期限 | 申诉/联系指引 |
| 通知为空 | 「暂无通知」空态 | 回首页 |
| 弱网 | 顶部细条「当前网络较慢，已切换省流模式」 | 自动恢复 |

### 9.4 人工帮助出口

- 全局页脚固定「联系我们」邮箱链接（mailto）；
- 异常页（5xx/封禁）附联系邮箱，不做在线客服（一期无此能力）。

## 十、非功能需求

### 10.1 性能指标（移动端，4G 中等机型基准）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| LCP | ≤2.5s | 首屏最大内容绘制（首图用缩略图占位） |
| INP | ≤200ms | 交互响应 |
| CLS | ≤0.1 | 瀑布流须按宽高比预留占位 |
| 首屏 JS | 首包 gzip ≤350KB | `/m/*` 页面独立分包，不进入主包 |
| 图片流量 | 列表仅加载缩略图 WebP | 预览图进详情才加载 |

### 10.2 兼容性

- iOS Safari ≥15（`env()`/`dvh`/`visualViewport` 基线）；
- Android Chrome ≥100、微信内置浏览器（X5/WebView）；
- 覆盖分辨率档位：360×800、390×844、430×932、768px 临界点。

### 10.3 安全与合规

- 全部请求走 HTTPS，沿用 Cloudflare Full 模式与 WAF `/api/` 跳过规则；
- 高危操作（上传/删除/申诉/资料修改）人机验证门不变，Turnstile ≤360px 自动 compact；
- 不新增任何本地存储敏感项；JWT 仍存内存 + httpOnly 约定与桌面端一致；
- 注册号、地区等公示信息遵循现有隐私规则（IP 仅存省份、不存明文）。

### 10.4 PWA 基础能力（一期范围）

- `manifest.json` + 图标，支持「添加到主屏幕」；
- Service Worker 仅做静态资源缓存，**不做** API 离线缓存与后台同步；
- 消息推送（Web Push）列入二期，一期以站内通知中心为准。
