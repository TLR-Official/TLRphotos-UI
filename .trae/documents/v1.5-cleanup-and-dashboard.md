# V1.5.0 数据清理与仪表盘修复 实施计划

## Summary

基于数据库实测制定精准方案：
- **匿名用户**：users 表无匿名账户、photo_likes/article_likes 无 'anonymous' 残留；唯一存在的匿名数据是 **photos 表 50 张 user_id IS NULL 的上传照片**。将删除这 50 张照片 + 调用 deleteFromOSS 删除其关联 OSS 文件，并修改 /upload 接口强制登录（与 V1.4.0 点赞强制登录策略一致）。
- **仪表盘数据显示问题**：根因是 [DashboardPage.tsx L24-32](file:///opt/tlr-photos-ui/TLRphotos-UI/src/admin/DashboardPage.tsx#L24-L32) 的 fetchData **完全没有 error 处理**——API 失败时 silently 不 setState，loading=false 后所有卡片显示 0。同时 `/api/admin/stats` 的 today 上传查询不按 zone 过滤（zone_master 看到全局数与本 zone 不一致），`/api/admin/photos/stats` L575 total 计算有运算符优先级歧义。
- **监控告警**：复用 `logAdminAction` + admin_logs 表（[adminService.ts L201-216](file:///opt/tlr-photos-ui/TLRphotos-UI/backend/src/services/adminService.ts#L201-L216)）+ 新增定时检查任务 + 前端仪表盘顶部告警条。零外部依赖。

## Proposed Changes

### Phase A：数据清理（一次性脚本 + 上传接口强制登录）

#### A1. 一次性清理脚本 `backend/src/scripts/cleanup-anon-photos.ts`
**作用**：删除 photos.user_id IS NULL 的 50 张照片 + 调用 deleteFromOSS 删除其关联 OSS 文件 + 写入 admin_logs 审计日志。脚本用完即删。

**关键逻辑**：
```ts
async function main() {
  await initDb();

  // 1. 查询所有匿名照片
  const anonPhotos = await db.all(
    'SELECT id, title, thumbnail_path, original_url, preview_url, watermarked_url FROM photos WHERE user_id IS NULL'
  );
  console.log(`[Probe] 找到 ${anonPhotos.length} 张匿名上传照片`);

  // 2. 生成元数据快照到 .ai/backups/ 作为审计证据（不阻塞删除）
  const backup = anonPhotos.map(p => ({
    id: p.id, title: p.title,
    thumbnail: p.thumbnail_path, original: p.original_url,
    preview: p.preview_url, watermarked: p.watermarked_url,
  }));
  fs.mkdirSync(path.join(__dirname, '../../.ai/backups'), { recursive: true });
  fs.writeFileSync(
    path.join(__dirname, '../../.ai/backups/anon-photos-cleanup.json'),
    JSON.stringify({ timestamp: new Date().toISOString(), count: backup.length, photos: backup }, null, 2)
  );

  // 3. 逐张删除 OSS 文件（4 个 URL 各自的 key）
  let ossDeleted = 0, ossFailed = 0;
  for (const p of anonPhotos) {
    for (const url of [p.thumbnail_path, p.original_url, p.preview_url, p.watermarked_url]) {
      if (!url) continue;
      try { await deleteFromOSS(extractKeyFromUrl(url)); ossDeleted++; }
      catch (e) { console.error(`[OSS Fail] photo=${p.id} url=${url}`, e); ossFailed++; }
    }
  }

  // 4. 删除数据库记录（photo_likes / photo_views 因 ON DELETE CASCADE 自动清理）
  const delResult = await db.run('DELETE FROM photos WHERE user_id IS NULL');
  console.log(`[DB] 删除 ${delResult.changes} 条 photos 记录`);

  // 5. 写入审计日志
  await logAdminAction({
    admin_id: 'system_cleanup_script',
    admin_name: 'System Cleanup',
    action: 'cleanup_anon_photos',
    target_type: 'photos',
    target_id: 'bulk',
    details: JSON.stringify({
      deleted_count: delResult.changes,
      oss_deleted: ossDeleted, oss_failed: ossFailed,
      backup_path: '.ai/backups/anon-photos-cleanup.json',
    }),
    ip: '127.0.0.1',
  });

  // 6. 验证清理结果
  const remaining = await db.get('SELECT COUNT(*) as cnt FROM photos WHERE user_id IS NULL');
  console.log(`[Verify] 剩余 user_id IS NULL 照片: ${remaining.cnt}`);
  if (remaining.cnt !== 0) throw new Error('清理未完成，仍有匿名照片残留');

  console.log('\n✅ 清理完成。审计日志已写入 admin_logs。');
}
```

**OSS key 提取**：从完整 URL 中提取 OSS key（OSS 删除按 key 而非 URL）。需要查看 ossService.ts 中 key 格式与 URL 的映射关系（执行时再确认）。

**安全清理**：
- 脚本执行前先 dry-run 模式输出将要删除的清单
- 元数据备份到 `.ai/backups/anon-photos-cleanup.json`（不阻塞删除，仅作审计证据）
- 删除后验证 `photos.user_id IS NULL` 数为 0
- 写入 admin_logs 记录删除数量、OSS 删除/失败计数、备份路径

### Phase B：仪表盘数据显示修复

#### B1. `/api/admin/stats` 加 zone 过滤 + 错误处理（admin.ts L707-731）
**问题**：today 上传查询 `SELECT COUNT(*) FROM photos WHERE DATE(created_at) = DATE('now')` 不按 zone 过滤，zone_master 看到全局数与本 zone 不一致。

**修改**：
- zone_master/zone_auditor 时 today 上传查询添加 `AND category = ?` 过滤
- 用 `Promise.allSettled` 替代 `Promise.all` 防止单个 SQL 失败影响全部
- 返回字段增加 `partial_error?: string`（部分失败时标注哪些字段失败）

```ts
router.get('/stats', adminAuthMiddleware, requireRole(['super', 'zone_master', 'zone_auditor']), async (req, res) => {
  const zoneFilter = (req.admin.role === 'zone_master' || req.admin.role === 'zone_auditor') ? req.admin.zone : null;

  const queries = {
    userCount: 'SELECT COUNT(*) as count FROM users WHERE is_active = 1',
    photoCount: zoneFilter
      ? 'SELECT COUNT(*) as count FROM photos WHERE category = ?'
      : 'SELECT COUNT(*) as count FROM photos',
    adminCount: 'SELECT COUNT(*) as count FROM admin_users WHERE is_active = 1',
    todayUploads: zoneFilter
      ? "SELECT COUNT(*) as count FROM photos WHERE DATE(created_at) = DATE('now') AND category = ?"
      : "SELECT COUNT(*) as count FROM photos WHERE DATE(created_at) = DATE('now')",
    pendingCount: zoneFilter
      ? "SELECT COUNT(*) as count FROM photos WHERE status = 'pending' AND category = ?"
      : "SELECT COUNT(*) as count FROM photos WHERE status = 'pending'",
  };

  const entries = await Promise.all(Object.entries(queries).map(async ([key, sql]) => {
    try {
      const row = await db.get(sql, zoneFilter || []);
      return [key, row?.count ?? 0, null];
    } catch (e) {
      return [key, 0, e instanceof Error ? e.message : 'unknown'];
    }
  }));

  const data = {};
  const errors = [];
  entries.forEach(([k, v, err]) => {
    data[k] = v;
    if (err) errors.push(`${k}: ${err}`);
  });

  res.json({
    success: true,
    data,
    ...(errors.length ? { partial_error: errors.join('; ') } : {}),
  });
});
```

#### C1. 新增 `/api/admin/dashboard/health` 接口（admin.ts）
**作用**：返回仪表盘关键数据一致性检查结果，供前端告警条读取。

```ts
router.get('/dashboard/health', adminAuthMiddleware, requireRole(['super', 'zone_master']), async (req, res) => {
  const checks = await Promise.allSettled([
    db.get('SELECT COUNT(*) as cnt FROM photos WHERE user_id IS NULL'),          // 匿名照片
    db.get("SELECT COUNT(*) as cnt FROM photo_likes WHERE user_id = 'anonymous'"), // anonymous 点赞
    db.get("SELECT COUNT(*) as cnt FROM article_likes WHERE user_id = 'anonymous'"),
    db.get("SELECT COUNT(*) as cnt FROM photos WHERE status NOT IN ('approved', 'pending', 'rejected')"), // 异常状态
    db.get("SELECT COUNT(*) as cnt FROM admin_logs WHERE action = 'dashboard_alert' AND created_at > datetime('now', '-1 hour')"), // 近 1h 告警数
  ]);

  const [anonPhotos, anonLikes, anonArtLikes, badStatus, recentAlerts] = checks.map(r =>
    r.status === 'fulfilled' ? r.value?.cnt ?? 0 : -1  // -1 表示查询失败
  );

  const issues = [];
  if (anonPhotos > 0) issues.push(`匿名照片: ${anonPhotos}`);
  if (anonLikes > 0) issues.push(`anonymous 点赞: ${anonLikes}`);
  if (anonArtLikes > 0) issues.push(`anonymous 文章点赞: ${anonArtLikes}`);
  if (badStatus > 0) issues.push(`异常状态照片: ${badStatus}`);
  if (recentAlerts > 0) issues.push(`近 1h 告警: ${recentAlerts}`);

  res.json({
    success: true,
    data: {
      healthy: issues.length === 0,
      issues,
      checked_at: new Date().toISOString(),
    },
  });
});
```

#### D1. 验证脚本 `backend/src/scripts/check-data-consistency.ts`

```ts
async function main() {
  await initDb();

  const checks = [
    { name: 'photos.user_id IS NULL', sql: 'SELECT COUNT(*) as cnt FROM photos WHERE user_id IS NULL', expect: 0 },
    { name: "photo_likes.user_id='anonymous'", sql: "SELECT COUNT(*) as cnt FROM photo_likes WHERE user_id='anonymous'", expect: 0 },
    { name: "article_likes.user_id='anonymous'", sql: "SELECT COUNT(*) as cnt FROM article_likes WHERE user_id='anonymous'", expect: 0 },
    { name: 'photo_views.viewer_key 非 user/ip 前缀', sql: "SELECT COUNT(*) as cnt FROM photo_views WHERE viewer_key NOT LIKE 'user:%' AND viewer_key NOT LIKE 'ip:%'", expect: 0 },
    { name: "photos.status 非 approved/pending/rejected", sql: "SELECT COUNT(*) as cnt FROM photos WHERE status NOT IN ('approved','pending','rejected')", expect: 0 },
  ];

  let allPassed = true;
  for (const c of checks) {
    const row = await db.get(c.sql);
    const actual = row?.cnt ?? -1;
    const passed = actual === c.expect;
    console.log(`${passed ? '✓' : '✗'} ${c.name}: expected=${c.expect}, actual=${actual}`);
    if (!passed) allPassed = false;
  }

  console.log(allPassed ? '\n✅ 所有一致性检查通过' : '\n❌ 存在异常，请排查');
  process.exit(allPassed ? 0 : 1);
}
```

## Assumptions & Decisions

### 已确认决策（来自用户）
1. **清理范围**：删 50 张匿名照片 + 禁未来匿名上传（与 V1.4.0 点赞策略一致）
2. **仪表盘问题场景**：普遍的"打开仪表盘就显示不出数据"（根因：API 失败 silently 显示 0）+ zone_master 看本 zone 全 0 + total 运算符优先级 + API 失败静默
3. **告警方式**：admin_logs + 前端告警条（零外部依赖）

### 内部决策（无需澄清）
- **元数据备份**：清理前生成 `.ai/backups/anon-photos-cleanup.json`（不阻塞删除，仅作审计证据）
